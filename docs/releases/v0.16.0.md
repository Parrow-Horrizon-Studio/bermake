# Bermake v0.16.0

This is the build for Bermake's first beta testers. It changes nothing about
modelling. It makes the Windows build from v0.15.0 clearer when something goes
wrong, and easier to report on when it does.

---

## Getting it running

Download `Bermake-0.16.0-windows-x64.zip` from the
[latest release](https://github.com/Parrow-Horrizon-Studio/bermake/releases/latest)
and unzip it anywhere. The build is not signed yet, so the first time you run
`Bermake.exe` Windows will show "Windows protected your PC"; click **More
info**, then **Run anyway**. If you used v0.15.0, delete its folder and use
this one instead; your preferences and logs carry over.

## When the 3D view cannot draw

Bermake still checks OpenGL every time it starts, before the main window
opens, by asking the driver what it supports and then drawing a small test
image. If the check fails, it explains why and offers to restart using
compatibility rendering. New in this release: if you choose **Close**
instead, or no restart is on offer, the 3D view no longer stays blank. A note
in its centre says what to do next: turn on **Help > Use Compatibility
Rendering** and restart, or, when that cannot help, use **Help > About
Bermake** to gather details for a bug report.

Compatibility rendering uses Mesa's CPU renderer, llvmpipe, and that is the
only supported setting in this build. The tester `README.txt` no longer
suggests choosing another Mesa driver: the Direct3D 12 driver closes Bermake
without a message, because a Microsoft file it needs is not included.

## Smaller changes you might notice

- **Help > About Bermake**, and the `Bermake.exe` Properties window, now say
  *Copyright (C) 2026 Parrow Horrizon Studio* (#138).
- The **Units** menu reads *Metric (mm)*, *Imperial (architectural)* and so
  on.
- `native-crash.log` no longer grows forever: once it passes 256 KB, Bermake
  keeps its most recent 64 KB at the next launch.

## Under the hood

The packaged build's self-test (`start /wait Bermake.exe --smoke-test
report.json`) now also decodes a JPEG, which proves the image plugin that
JPEG textures depend on is in the zip, and the build fails if the self-test
ever stops reporting its two graphics checks. The 3D view now judges each new
OpenGL context on its own, so a good context that follows a bad one draws
normally. A failure while unpacking the bundled Mesa during a build now says
which tool failed and how. Every CI job now has a time limit, so a stuck test
fails within 90 minutes instead of running for six hours. Most of these come
from the follow-up list in #139, which stays open for the rest.

## Reporting a problem

Nothing changed here: **Help > About Bermake > Copy details** puts your
versions and graphics renderer on the clipboard, and the logs are in
`%LOCALAPPDATA%\Parrow Horrizon Studio\Bermake\logs`. Attach `bermake.log`, and
`native-crash.log` if Bermake closed by itself.

## Known limits

The same as v0.15.0: the build is not signed, there is no installer, there is
no `.berm` file association yet (#76), and this release is Windows only;
macOS and Linux still run from source.
