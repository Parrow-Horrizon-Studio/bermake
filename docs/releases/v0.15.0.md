# Bermake v0.15.0

This is the first release you can download and run without building anything.
Every release before this one meant assembling an MSVC, vcpkg and CMake
toolchain before you could even see the application. From here on: download a
zip, unzip it, double-click.

---

## Getting it running

Download `Bermake-0.15.0-windows-x64.zip` from the
[latest release](https://github.com/Parrow-Horrizon-Studio/bermake/releases/latest)
and unzip it anywhere. The build is not signed yet, so the first time you run
`Bermake.exe` Windows will show "Windows protected your PC"; click **More
info**, then **Run anyway**. The zip includes a `README.txt` covering
compatibility rendering and how to report a problem, worth a read before
anything else.

## If the 3D view does not work

Bermake checks the OpenGL context it gets on first launch. If the driver
reports a version below 3.3, or a shader fails to compile, you will see a
message naming the version and renderer it found, instead of a black viewport
or a crash. That message offers to restart using compatibility rendering,
which switches Bermake onto a Mesa build carried inside the zip and runs on
Mesa's CPU renderer, llvmpipe, so it works even with no usable GPU driver at
all. You can also turn it on yourself from **Help > Use Compatibility
Rendering**, or force it for a single launch with `--compatibility-rendering`.

## Reporting a problem

**Help > About Bermake** has a **Copy details** button that places your
Bermake, Qt, PySide6 and Python versions, your OpenGL renderer, and whether
compatibility rendering is active onto the clipboard, ready to paste into an
issue. Everything Bermake logs during a session, plus a separate crash log for
a native crash that takes the process down before Python can react, lives in
`%LOCALAPPDATA%\Parrow Horrizon Studio\Bermake\logs`. To check the build
itself is working before chasing a real problem, run it with
`--smoke-test report.json`.

## Under the hood

The version now comes from a single place, `pyproject.toml` (#130), instead
of four hand-maintained literals that could drift apart. Every build is
tested against a real installed wheel in a clean virtual environment rather
than the editable install developers use (#136), which is what catches a
packaging mistake before a tester does. The bundled Mesa build is pinned to
26.2.3 by its SHA-256 checksum, so what ships is what was tested. And the
README's status section, which still said v0.8.0, now describes what this
build actually is (#135).

## Known limits

The build is not signed, so the SmartScreen warning above is expected, not a
sign of a problem. There is no installer: unzip and run, and delete the
folder to remove it. There is no `.berm` file association yet (#76). And this
release is Windows only; macOS and Linux still run from source.
