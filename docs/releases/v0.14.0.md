# Bermake v0.14.0

Pluton is now called Bermake. Nothing about how the application behaves has
changed in this release: it renames, it does not improve. The rename does
touch the file format, the launch command and the settings store, so please
read the four things below before you do anything else. Any one of them can
waste your afternoon if it catches you by surprise.

---

## Read this first: four things break

### 1. Documents written by 0.13.0 and earlier cannot be opened

The native format's identity changed along with everything else, and there is
deliberately no conversion path from the old identity to the new one. Opening
an old file does not fail with a generic error: Bermake recognises the old
format by name and tells you so directly, rather than guessing at a file it
was never meant to read.

If you still need documents from 0.13.0 or earlier, keep a copy of the 0.13.0
build around to open them. There is no importer for the old format, and none
is planned; the identity change is the point of this release, not a side
effect of it.

### 2. The launch command changed

It was `pluton`. It is now `bermake`. Update any shortcut, script or alias
that starts the application by name.

### 3. Stored preferences reset

The application's Qt identity changed along with its name, so the settings
store Bermake reads from is a new one, separate from whatever Pluton wrote to.
Concretely: your theme returns to Light, the welcome window comes back even if
you had turned it off, and the default template returns to Architectural.
Nothing here is lost that cannot be reset again in a few clicks, but the
application will look like it forgot you until you do.

### 4. The file extension is `.berm`, was `.pluton`

This follows from point 1: a document you save today is a `.berm` file, and
opening it again later requires a Bermake build, not a Pluton one.

---

## Why the rename

Microsoft holds a trademark on "Microsoft Pluton", a silicon security
processor built into Windows PCs. It is a different class of goods, so a
conflict was never certain, but the name was a poor asset regardless:
searching for "Pluton" turns up Microsoft's product, not this one. Bermake is
coined, so it is searchable and defensible.

This release is a rename and nothing else. The Python package, the C++
headers, the CLI entry point, the native file format and every reference in
code, tests and docs moved to the new name across two mechanical commits. No
modeling behaviour changed and no bug was fixed along the way.

---

## Reporting a problem

Open an issue at
<https://github.com/Parrow-Horrizon-Studio/bermake/issues>. Useful things to
include: the version from the console line Bermake prints at startup, and what
you expected instead.

If Bermake refuses to open a file, check whether it was saved by 0.13.0 or
earlier before anything else. That is expected behaviour, not a bug, and is
covered above.
