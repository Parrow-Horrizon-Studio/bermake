# M7.12 Autosave and crash recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tester who hits a crash, power cut or forced close loses at most one autosave interval of work, and gets it back on the next launch, without their own `.berm` ever being overwritten unasked (#77).

**Architecture:** A new `python/bermake/recovery/` package holds the parts that need no window: the recovery folder (`store.py`), process liveness (`liveness.py`), the startup query (`startup.py`) and the pure autosave scheduler (`scheduler.py`). `MainWindow` owns one session per document, ticks the scheduler from a 1 s `QTimer`, and writes autosaves through the existing atomic `save_document`. `app.py` runs recovery between `window.show()` and the Welcome dialog.

**Tech Stack:** Python 3.13, PySide6 6.11, ctypes (Windows process APIs), pytest + pytest-qt, ruff.

**Spec:** `docs/2026-10-04-M7.12-autosave-design.md` (approved 2026-10-04). It is binding. Section references below (4.2, 4.5 and so on) point into it.

## Maintainer decisions (from the spec, binding)

- D1. Autosaves live in `<AppLocalDataLocation>/recovery` (on Windows `%LOCALAPPDATA%\Parrow Horrizon Studio\Bermake\recovery`), never next to the user's drawing.
- D2. Default interval 5 minutes; choices Off, 1, 5, 10, 30 minutes.
- D3. The interval is set in a **File > Autosave** submenu of five checkable entries. There is no Preferences window.
- D4. Recovery asks first and opens the work as unsaved, not tied to the original file. Save goes through Save As, pre-filled with the original folder and name.
- D5. An autosave becomes due at the interval, runs at the next pause (2 s without input, no mouse button held, no tool holding uncommitted changes, no modal open), and is forced 60 s after becoming due, still never mid-gesture or under a modal.
- D6. Out of scope: older autosave versions, a backup copy on every Save, recovering several documents at once.

## Review Focus

The failure modes most likely to bite a tester that the spec implies but no obvious test exercises. Each has its test in the owning task.

1. **The computer sleeps for hours, or the clock changes.** The scheduler measures time with a monotonic clock, and waking from sleep produces one due autosave, not a burst. Task 2, step 1.
2. **A recovery file vanishes or is locked between listing and loading** (antivirus, another Bermake, the user deleting the folder). Startup shows no traceback, quarantines or skips the session, and still reaches the Welcome dialog. Task 6, step 1.
3. **An autosave left by a newer Bermake build** (schema newer than this build reads) is quarantined with the "could not be opened" message, never crashes startup and is never deleted. Task 6, step 1.
4. **A second Bermake starting while the first is still open** never offers the first one's live session. This is checked through the real `_build_main_window` path, not only `process_is_running`. Task 6, step 1.
5. **An Untitled drawing that is later saved under a name:** once the recovery files are deleted at Save, the next change's autosave records the new `original_path` and display name. A crash after that recovers under the right name. Task 4, step 1.

**Interfaces:**
- Produces, in `store.py`:

```python
RECOVERY_FORMAT = "bermake-recovery"
RECOVERY_VERSION = 1

@dataclass(frozen=True)
class SessionMeta:
    session_id: str
    original_path: str | None
    display_name: str
    saved_at: str            # ISO 8601 with offset, e.g. "2026-10-04T14:32:05+08:00"
    app_version: str
    pid: int
    process_started_at: str  # ISO 8601 with offset

@dataclass(frozen=True)
class RecoverySession:
    meta: SessionMeta
    berm_path: Path
    meta_path: Path

class RecoveryStore:
    def __init__(self, folder: Path) -> None: ...
    folder: Path
    def berm_path(self, session_id: str) -> Path: ...
    def write(self, meta: SessionMeta, write_berm: Callable[[Path], None]) -> None:
        """Create the folder if needed; call write_berm(<id>.berm) (save_document is
        already atomic); then write <id>.json atomically (temp file + os.replace).
        The JSON is written only after write_berm returns. Raises OSError on failure."""
    def list_sessions(self) -> tuple[list[RecoverySession], list[str]]:
        """(valid sessions, ids that were quarantined). A .json without its .berm,
        a .berm without its .json, unreadable or wrong-format JSON: quarantined,
        never returned. Ignores *.broken.* and *.tmp files."""
    def delete(self, session_id: str) -> None: ...   # missing files are fine
    def quarantine(self, session_id: str, reason: str) -> None:
        """Rename <id>.berm -> <id>.broken.berm and <id>.json -> <id>.broken.json
        (whichever exist), never delete; log the reason at WARNING."""
    def hand_over(self, old_id: str, new_meta: SessionMeta) -> None:
        """Rename <old>.berm to <new>.berm and write <new>.json from new_meta;
        remove <old>.json. Used by Recover (spec 4.5)."""
```

- Produces, in `liveness.py`: `current_process_started_at() -> str` (ISO 8601 of this process's creation time) and `process_is_running(pid: int, started_at: str) -> bool`. It is True only if the PID exists and its creation time is within 2 s of `started_at`. When liveness cannot be determined, it returns True (spec 4.5: unknown counts as running).
- Produces, in `startup.py`: `recoverable_sessions(store: RecoveryStore, is_running=process_is_running) -> list[RecoverySession]`. These are the valid sessions whose writer is not running, newest `saved_at` first.

### Task 2: The autosave scheduler

**Files:**
- Create: `python/bermake/recovery/scheduler.py`
- Test: `tests/test_autosave_scheduler.py`

**Interfaces:**
- Produces:

```python
INTERVAL_CHOICES = (0, 1, 5, 10, 30)   # minutes; 0 = Off
DEFAULT_INTERVAL = 5
IDLE_SECONDS = 2.0
FORCE_AFTER_SECONDS = 60.0

class AutosaveScheduler:
    def __init__(self, interval_minutes: int, clock: Callable[[], float] = time.monotonic) -> None: ...
    interval_minutes: int                 # read-only property
    changed_since_autosave: bool          # read-only property
    def set_interval(self, minutes: int) -> None: ...   # restarts the countdown
    def note_change(self) -> None: ...                  # document changed
    def note_saved(self) -> None: ...                   # autosave or user Save succeeded: clear flag, restart countdown
    def note_failed(self) -> None: ...                  # autosave failed: keep flag, restart countdown
    def should_save(self, *, idle_for: float, button_held: bool,
                    tool_busy: bool, modal_open: bool) -> bool: ...
```

  `should_save` is called once per tick. It returns True when all of these hold:
  - the interval is not Off, `changed_since_autosave` is set, and `clock() - countdown_start >= interval_minutes * 60`
  - the save is safe: `not button_held and not tool_busy and not modal_open`
  - either `idle_for >= IDLE_SECONDS`, or the save has been due for at least `FORCE_AFTER_SECONDS`

  "Due since" is the moment the interval elapsed while there were changes. It is measured with the same clock.

- [ ] **Step 1: Write the failing tests** with a fake clock (a list holding the current time, advanced by the test). Cover:
  - nothing while unchanged
  - nothing while Off, even with changes
  - nothing before the interval
  - due, not idle: False; then idle 2 s: True
  - due and never idle: True at exactly 60 s overdue, but False at 61 s if `button_held`, `tool_busy` or `modal_open` is set
  - `note_saved` clears the flag and restarts the countdown
  - `note_failed` keeps the flag, restarts the countdown, and the next due point is one interval later
  - `set_interval` restarts the countdown
  - an unknown interval passed to `set_interval` is stored as given (the preference layer validates)
  - **Review Focus 1:** advance the fake clock by 3 hours in one step with changes pending. The first idle tick returns True. After `note_saved`, no further True arrives until another change plus a full interval. One wake gives one save, not a burst.
