### Task 2: Note over the 3D view when OpenGL is unusable (D3)

- A centred, word-wrapped note over the viewport (a child QLabel or a small overlay widget owned by MainWindow or ViewportWidget; choose the smallest that works without a GL context, because in the no-context case `paintGL` never runs).
- Shown when the startup preflight outcome is REPORTED (passed into the window the same way `note_gl_reported_at_startup()` is today) and when the window's own `_on_gl_unavailable` prompt is declined or offers no restart.
- Text when a restart is available: `Bermake cannot draw the 3D view on this computer. Turn on Help > Use Compatibility Rendering and restart Bermake.` Text when it is not (compatibility rendering already active, or Mesa missing, or it failed to enable): `Bermake cannot draw the 3D view on this computer. Help > About Bermake has details to include in a bug report.`
- Never shown on a healthy start. Follows the theme's text colour; readable on the dark and light viewport backgrounds.
- Tests: shown for REPORTED with and without restart (the two texts); not shown for OK; shown after a declined window prompt; not shown when the prompt is accepted (restart path). Mutation-check.
- Docs: leave `docs/releases/v0.15.0.md` alone (v0.15.0 has shipped); describe the note in `packaging/README.txt` where the OpenGL message is described.

### Task 3: Diagnostics behaviour and code tidies (#139 Behaviour 2 and 4, Code tidiness 1 to 5)

- `_gl_failed` reset: when `initializeGL` runs again, the verdict is re-evaluated from a clean state (reset `_gl_failed` at the start of the check), so a good context after a bad one renders. Repeated failures need no extra de-duplication. Test with the existing viewport verdict test pattern.
- `native-crash.log` bound: at startup, if the file is larger than 256 KiB, keep its last 64 KiB (cut at a line boundary) before appending the new session header. Test with a tmp file.
- `logs._qt_levels`: build the mapping once (module level or cached on first use); behaviour unchanged; existing tests pass.
- `apply_compatibility_rendering`: resolve the Mesa lookup at call time, the same way `mesa_restart_available` does; test that patching `app.default_mesa_dir` takes effect.
- `fetch_mesa`: an extractor failure raises `MesaFetchError` naming the extractor command and its exit code (chain the original); `tools/package_windows.py` keeps working; test with an injected failing runner.
- `cpp/include/bermake/version.h` doc comment: replace the literal example with `"X.Y.Z"`; run clang-format 18.1.8 on it.
- Mesa file names: add one test that asserts `tools/fetch_mesa.py` `MESA_FILES`, `compat_rendering.MESA_LOADER`/`MESA_DRIVER` and the names in `packaging/bermake.spec` agree (read the spec as text). No production refactor.
