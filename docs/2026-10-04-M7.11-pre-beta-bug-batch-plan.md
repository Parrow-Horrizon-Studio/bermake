## Review Focus

These are the failure modes most likely to bite a tester that no single task's obvious tests would catch. Each has its test assigned to a task below.

1. **Undo of an edge split on a concave face** must restore correct triangles, not the fan, so undo never brings the filled-in notch back. Task 6, step 1.
2. **Paint, stored UVs and texture placement survive re-triangulation.** Splitting an edge of a painted, textured concave face keeps every material and corner UV. Task 6, step 1.
3. **Old files self-heal.** A face saved while its triangles were fan-corrupted loads with correct triangles, because loading rebuilds triangles from the loop. Task 6, step 1, as a regression pin.
4. **A palette switch at runtime** (Light to Dark while Bermake is open) rebuilds the checked-icon ink, so a checked tool stays readable after the switch. Task 5, step 1.
5. **Both arc endpoints on the same edge.** The first split retires the edge ID, so the second endpoint must be resolved against the new sub-edges, or it raises or splits nothing. Task 7, step 1.

- Produces: C++ `void HalfEdgeMesh::set_face_triangles(int face_id, const std::vector<int>& flat_vertex_ids)`, bound as `mesh.set_face_triangles(face_id, flat_vertex_ids)`. It replaces the face's stored triangulation. It validates before changing anything: the face is live, the length is a multiple of 3, and every ID is a vertex of that face's boundary loop. On failure it throws `std::invalid_argument` (a Python `ValueError`) and leaves the face unchanged. **Triage:** `HalfEdgeMesh::split_edge` rebuilds each incident face as a fan from `loop[0]` (`halfedge.cpp:987-998`), and `dissolve_edge` does the same for the merged face (`:746-759`). Neither Scene wrapper re-triangulates, and both the renderer and picking use those triangles. Repro: a U-shaped face of area 7 has 8 edges. Splitting any of them at `t = 0.5` yields triangles whose absolute areas sum to 11, so the notch is filled and clickable. This is reachable today from a Line snap to an edge midpoint (`SplitEdgeCommand`) and from erase-to-merge. Loading a file rebuilds faces with `add_face_from_loop`, which earcuts, so saved files are unaffected.
